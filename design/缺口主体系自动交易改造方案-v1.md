# 缺口主体系自动交易改造方案 v1

日期：2026-10-31。状态：设计提案，未实现、未验证收益。已核验代码基线：50559aa。承接《自动交易优化设计-v2.2.md》和《事件器设计-v1.md》。不设计外部行情采集，不使用自训练模型；通用多模态 API 负责解释，程序负责事实与执行。

参考资料：[z说交易缺口体系学习整理](https://abu-learning-site.vercel.app/z-trader)。该网页是二手学习整理，本方案不把其中概率、机构意图或个人理论视为已验证事实，也不据此修改账户风险参数。下文的缺口定义是项目工程契约，不能冒充原作者精确定义；需要逐类用原始图例校准。

## 1. 总体决策

将缺口从“附加特征和研究卡”提升为机会组织的主索引：

```text
突破尝试 → 缺口建立 → 保持/回补/回补失败 → 目标到达与反应
                          ↓
                 场景假设与机会生命周期
                          ↓
                 具体策略触发 → 风控 → 执行
```

主体系不是“所有信号必须有缺口”，也不是“有缺口必回补”。它意味着背景解释、观察位置、机会接续和复盘优先围绕缺口生命周期组织。三推、通道、MM、高周期位置仍作为背景或独立位置证据，不能全部删掉。

首版只开发一个明确策略族：**未回补缺口的顺势恢复**，其中二次回补失败为可独立评估的子型。向缺口回补、补完后恢复、突破失败反向交易先保留观察记录，不能混进同一个 G1 条件矩阵。

## 2. 当前代码可以复用什么

| 当前模块 | 当前语义及问题 | 改造决策 |
|---|---|---|

| gaps._run_anchor | 每个锚返回第一段记录，关闭后没有完整重复立账周期 | 同锚每次重新立账创建新 gap_id，保留 parent/source 关联 |
| gaps origin 锚 | 强 K 自身极值出生即立账，不满足普通锚的整根位外规则 | 独立命名为 origin_reference，未验证前不等同于正式缺口 |

| G1 研究卡 | 混合回补方向、落点、未遂恢复；“对侧边缘”与单线定义不匹配 | 冻结旧卡，另立新策略 ID；用明确价位关系决定方向 |
| judge/*prompt* | 机器趋势路由卡，缺口卡额外附加 | 改为缺口场景目录及按场景加载详细卡 |

| gate / replay | 纪律和模拟基础可用，stop 语义待修 | 复用通用风控；新策略规则注册化，先修成交再比较效果 |

这不是把提示词写成“多看缺口”。缺口的身份、时间、方向和生命周期必须成为持久领域对象。

## 3. 缺口不能只有一个混用定义

首版支持两类事实对象，其他类别仅作为待核验候选。默认策略只交易通过定义审定的一类，不把两个类别样本直接合并。

### 3.1 anchor_separation：锚线分离

继承现有普通锚逻辑并显式版本化：锚在突破前可见；收盘从锚一侧穿到另一侧，形成 pending；当前或随后整根 K 线处于突破侧，确认 open。穿越根自身触线不取消 pending，之后在整根分离确认前触线则取消 pending。

- 上破：整根 low > anchor 后 open，support_side=up；价格通常在锚上方。
- 下破：整根 high < anchor 后 open，support_side=down；价格通常在锚下方。
- 立账后首次 low <= anchor <= high 记录 anchor_touched，gap 关闭。
- 这是“与锚分离”的操作定义，不声称整个区域从未成交。

### 3.2 range_gap：相邻整根区间分离

作为独立研究类别：若当前 low > 前 high，上行区间 [前 high, 当前 low]；若当前 high < 前 low，下行区间 [当前 high, 前 low]。形成根收盘时才可确认，填补检测从之后的 bar 开始。

上行区间从上边缘进入为 partial_fill，触及下边缘为 full_fill；下行镜像。区间固定，remaining_zone 是派生值，不能修改原始 zone。相邻区间未覆盖不等于所有交易所或更细粒度都没有成交。

### 3.3 后续类别

body_gap、signal_entry_reference、measuring_gap_role 分别设计，不共用一个含糊 gap 字段。measuring 是某个缺口的解释角色，不自动创建另一份事实。信号触发位是 reference，不能直接套用缺口回补规则。

网页的“精准 MM 缺口”只能在目标反应发生后形成解释标签；不能事后回写成早已知道的入场依据。所谓“最后一个缺口”明确为当前同方向同周期仍开放且形成时间最晚的对象，不附带“最强机构发动”的事实断言。

## 4. 核心数据对象

| 对象 | 必须字段 |
|---|---|
| Gap | id、kind、definition_version、symbol、timeframe、direction、anchor/zone、source_evidence、source_available_at、opened_at、observed_at、state |
| GapTest | id、gap_id、sequence、started_at、approach_side、closest_price、threshold_snapshot、ended_at、result、confirmed_at |
| GapEvent | id、gap_id、test_id、type、event_time、observed_at、snapshot_id、price_evidence |
| GapHypothesis | gap_ids、scene、claims、evidence、counterevidence、model/version、cutoff_at |
| Target | id、source_gap_ids、method_version、anchor_bar_ids、formula、price、created_at、available_at、status |
| Opportunity | id、strategy_id/version、primary_gap_id、supporting_gap_ids、test_id、conditions、state、revision |

Gap.state = pending/open/partially_filled/filled/invalidated；anchor 类无 partially_filled。invalidated 表示数据修订或来源不可用，不能与价格回补混同。filled 记录保留，图上可隐藏但审计不删除。

trapped_side 改为解释字段 hypothesis_trapped_side，可由 direction 推断一个假设，但不能证明真实仓位或成本。价格结构事实与参与者故事分别存储。

每个事实保存 confirmed_at：用下一根证据确认上一根测试失败时，最早只能从下一根确认时刻参与决策。追加未来数据不得改变已经发布的历史事实；修正必须追加 correction 事件而非静默覆盖。

## 5. 回补测试与事件

事件列表：GAP_OPENED、TEST_STARTED、PARTIAL_FILL、ANCHOR_TOUCHED、FULL_FILL、TEST_REJECTED、TARGET_TOUCHED、TARGET_RESPONSE_ASSESSED、GAP_INVALIDATED。

TEST_STARTED 代表价格进入预先定义的监控区，不代表一定触到锚或缺口区。监控区参数按发布政策在机会创建时冻结，不能用后来的均幅重新算历史距离。

一次靠近过程只有一个 GapTest；带内连续多根不能计成多次失败。下一次测试必须有已记录的离开及返回，具体与事件器 v1 的测试边界一致。等待本次行为进一步成立使用 new_evidence，不能强制离开再回来。

TEST_REJECTED 需明确证据：尚未触发该 gap 定义的 full_fill/anchor_touched，且满足策略冻结的离开条件。确定性代理与 AI 的“回补力度减弱”解释分开保存。不能仅以 attempts >= 2 宣布高质量二测。

同根出现填补和反向收盘时，按价格事实先终结旧 gap，允许另立“填补后恢复”研究机会；不得为了顺势策略继续有效而把已补缺口改成未补。

## 6. 场景判断不使用单一机械分数

AI 读取当前及已关闭缺口序列、两侧目标和图像，输出以下场景候选及反证：

- continuation_supported：一侧缺口保持，反向推进多次未完成回补。
- weakening：缺口逐渐回补，跟随减弱，原趋势解释受挑战。
- two_sided：两侧均有相关开放结构，优势不明确。
- transition_candidate：原趋势相关缺口被补后仍无恢复，反向推进出现新的结构。
- unresolved：证据不足或矛盾。

这些是解释标签，不由“多少个缺口”投票，也不自动升级为停牌规则。网页中数字概率不写入代码；逆势 stop 是否赚钱需要明确的假设下单、止损、目标和成本规则，未实现之前只能作人工研究标签。

## 7. 策略族拆分与首版边界

| 新策略 ID | 目标行为 | 首版状态 |
|---|---|---|
| GC1 | 未补缺口附近回补失败后，沿缺口形成方向恢复 | 首个影子策略 |
| GC2 | 缺口回补完成后出现恢复证据 | 只记录，需独立定义失效与方向 |
| GF1 | 价格向尚未回补的缺口推进 | 只记录，不能与 GC1 合并 |
| GR1 | 原缺口失效且反向结构建立后的反转 | 后续研究，不因一次填补直接交易 |

方向示例：上破锚 100、价格在 110，回到 101 未触 100 后转强；GC1 候选方向为 long。若从 110 做向 100 的回补，则是 GF1 short。两者不是同一种“缺口方向”。下破情况镜像。

G1 旧卡不重命名冒充 GC1；保留历史 ID 与条件解释。GC1 有独立 schema、规则注册和报告分母。多策略同时出现时沿用冲突记录，不靠列表顺序选择。

### 7.1 GC1 必须项

- R1：primary_gap 可追溯、仍 open，且属于已经审定的定义类别。
- R2：本次回补测试及拒绝证据已确认；选择 second_test 子型时须有两个独立测试，而非两次模型回答。
- R3：候选方向与 gap.direction 相同，当前图读无冻结否决证据。
- R4：策略允许的入场触发已明确，止损以价格结构失效为依据；所有引用在快照内。
- R5：提前记录的首目标与当前可执行价格支持既有净 RR 等风控要求。

加分项：独立来源位置叠加、高周期同向、三推衰竭、目标到达后的反应。不能因缺任意加分项拒绝已满足必要条件的机会。是否强制两个独立位置来源需作为策略版本决策，不能把页面口号自动变成全局门槛。

否决项：gap 已关闭/数据不可信、结构失效、关键反证 unknown、必要目标无法核对、当前计划不通过既有纪律。对方目标未完成作为结构化反证记录，不直接套用“所有顺势单一律禁止”；若研究证明该条件必要，再通过独立策略版本发布。

R3 中的具体反证清单及 R4 允许触发动作必须在 GC1 卡定版时逐条写明；本方案不是仅凭“转强”即可下单的生产卡。未完成卡片与案例审定前只允许观察模式。

## 8. 目标账本

目标不是事后挑一个最吻合的 MM。每个 Target 要保存计算锚点、公式和首次可见时间；首版只开放一种经图例审定的投影方法，其他作为非交易参考。

目标到达只发事实事件。到达后的拒绝、延续或停滞由新证据判断；“未到目标”需要明确可观察事件，不能靠无限等待定义。

缺口关联的投影角色可以因其定义要求的缺口关闭而失效；几何目标仍作为历史记录存在。是否继续用作其他策略目标必须显式新关联，不能删除记录掩盖先前预测。

首目标由冻结策略规则选择最近的相关有效阻挡结构/目标，不能为凑 RR 忽略近处阻力。止损、目标、空间和成交成本仍由现有 gate 核验，不因改为缺口主体系而降低门槛。

## 9. 自动交易接线

```text
外部快照
 → Snapshot 时间与数据核验
 → 因果 GapBook + TargetBook
 → 缺口事件及测试序列
 → AI 场景解释/GC1 行为核验
 → Opportunity 持续等待
 → 公共 DecisionService
 → Gate + 账户风险预占
 → 执行器、保护单与对账
 → 决策/执行/收益三本复盘账
```

现有 market 型 stop 语义修复是前置条件。GC1 首版使用明确 stop_market 或行为已完成后的 market；不盲挂 limit，不把缺口测试本身当成交。所有订单从真实提交之后才可能成交。

旧地图位置资格暂时保留。缺口机会已触发但旧收盘位置检查阻断时，单独标 POSITION_POLICY_BLOCKED，记录可评估计划但不提交。是否采用 gap 专属资格须单独对照，不能把这类阻断误判为缺口策略没机会。

执行与仓位管理沿用 v2.2；已有保护不依赖模型响应。缺口被补是事实，是否退出取决于持仓策略冻结的失效条款，不能把“所有缺口被补”统一等同于平仓。

## 10. 工程改动顺序

| 批次 | 文件/模块 | 交付 | 验收 |
|---|---|---|---|
| G0 定义与数据审计 | 新 gap contracts、fixtures；旧 gaps.py 只读基线 | 两类事实定义、方向样例、历史影响清单 | 图例可核对，未知定义不交易 |
| G1 因果账本 | perception/gap_book.py、gap_events.py | 稳定 ID、可见时间、完整 lifecycle、测试轮次 | 前缀不变性、逐根与批量结果一致 |
| G2 目标与解释 | target_book、judge 缺口场景 prompt | 已知时间目标、图数证据、反证 | 无事后改锚、无虚构参与者事实 |
| G3 单策略影子 | GC1 卡/规则注册、Opportunity 接线 | 唯一明确策略、持续等待及全漏斗 | 不多等一根、不合并回补与恢复方向 |
| G4 公共执行 | 复用 v2.2 T02/T08 | 正确订单语义、风险与保护 | 未触发不成交、超时不重单、恢复对账 |
| G5 评估与发布 | eval、Gold、版本配置 | 冻结对照及前向报告 | 质量门槛与用户上线授权齐备 |

最小闭环不需要一开始支持所有缺口种类和四类策略。先把 anchor_separation 的 GC1 轨迹做好；range_gap 独立分层评估，确认可兼容后才纳入。

## 11. 必须通过的测试

1. 前缀不变性：追加未来 K 线，不改变过去已确认事件的价格阈值、身份及 confirmed_at。
2. 当前才识别的 swing 锚，不能在其 available_at 之前生成前向缺口。
3. 下一根确认未遂时，决策不能提前到前一根。
4. 一次连续靠近不能算两次测试；离开返回后才能递增。
5. 同锚旧 gap 关闭后再次建立，新 ID 与旧记录共存。
6. anchor 触线即关闭；range_gap 部分填补不误记全补；形成根不立即填补自己。
7. origin_reference 不能被缺口策略当作已验证 open gap。
8. 上破缺口的 GC1 做多、GF1 向下回补做空；镜像场景对称。
9. 满足 required、缺 enhancing 时不增加无依据等待。
10. 同根补完再反弹，旧 gap 必须关闭，不为保留 GC1 而更改事实。
11. 模型无法确认场景时写 unknown，API 失败另记，不伪装策略空仓。
12. 目标事后出现反应不能倒填其角色认定时间。
13. stop 未触发、跳空和历史触及严格遵守统一成交语义。
14. 旧地图资格阻断单列，不把研究候选记成实际订单。

## 12. Gold、评估与改进

Gold 按完整轨迹标注：缺口是否存在、何时可知、测试是第几次、事实是否回补、哪个策略方向、当时允许什么行动。先冻结这些标签，再揭示后续收益。争议的背景解释保留多种可接受答案，不用盈亏裁定。

数据从未被事件器预筛的行情段抽样，包含无缺口、双向缺口、填补后继续、未补但反转、强信号失败等反例。按标的、时间段、方向、周期和缺口类别分层，相关窗口不得当独立样本。

对照分步做：先因果账本新旧差异，再测缺口场景对候选质量的影响，再测 GC1。订单语义修正、位置资格修改和策略修改不在同一实验同时发生。

报告包括缺口事实精确率/召回率、测试轮次误差、人工审定机会召回、错误候选率、无依据新增条件率、unknown、位置政策阻断、成交偏差与成本。收益单独报告样本数和不确定性，不因交易更多就判定更好。

## 13. 定稿前的具体选择

推荐首版路线已明确：anchor_separation、GC1、通用模型图数混合、无提前限价、既有风险纪律。以下需要在 G0/G3 的审定产物中完成，未完成不进入生产策略：

- 用原始图例确认工程缺口定义与所学体系的对应关系。
- GC1 每项必要条件、取消条款、触发动作及结构止损逐条定版。
- 冻结监控带和测试离开政策，区分代理指标与价格行为解释。
- 选择唯一首版 MM 方法及首目标选择规则，写出可复算样例。
- 确定评估阈值、执行产品和风险配置；这些不能由模型自行填入。

方案的中心是“缺口事实账本驱动的持续机会管理”。它改变机会组织与判断上下文，不以一个新的缺口硬筛选器替换旧形态硬筛选器。
