# 通用大模型 API 驱动的价格行为自动交易与学习方案

日期：2026-10-30。依据用户本轮明确方向：目标是 AI 自动交易；核心是学到可迁移的价格行为知识、有效复盘进步；使用通用大模型 API，无自有模型；遵守纪律且依据合理的亏损可属预期内，判断失误与违纪须分别识别。

## 一、什么叫“学会”

普通 API 请求不更新模型权重，也不默认保留之前的交易记忆。本项目的学习载体是外部系统：版本化规则、审定案例、可检索经验、确定性特征、决策记录与独立评估。API 模型负责在给定上下文内推理。

“学会”的验收不是能复述规则、拟合 gold 或解释过去的走势，而是在未见过的行情中：能指出当时可观察的证据；正确区分符合条件与仅外形相似的 setup；写出可验证的失效条件；在冻结测试上减少判断与纪律错误，并在足够的真实成本样本上检验表现。

持续改进包括三种不同变化，必须分别记录：知识表述更准确；提示和案例检索让模型更稳定地执行已有规则；确定性代码纠正感知或风控缺陷。均不宣称为模型权重已经训练。后续若 API 提供合适的微调能力，再独立评估其必要性。

## 二、教学材料如何组织

### 规则层：可操作的知识

每条规则保存：适用语境、前置条件、结构锚点、触发、失效条件、例外边界、证据来源和版本。明确“本系统交易纪律”与“待验证的市场假设”。禁止把未验证倾向包装成市场定律。

沿用 knowledge/core.md、setups/ 和确定性 perception。修复两腿、CLV、毛/净 RR、信号根与决策根等口径差异后再用作教学。

### 案例层：解释为什么成立或不成立

案例至少包括决策点、当时可见 K 线、结构与证据引用、候选条件逐项检查、主备假设、计划、失效条件和审定意见。结果单独保存，不在盲判阶段暴露。

成对选择相似形态：位置合格/不合格、第一腿/第二腿、真突破证据充分/不足、可交易/费用吃掉空间。也必须包含正确决策亏损与错误决策盈利，避免教会模型以结果解释规则。

改变单一关键条件的合成对照可测试规则理解，但合成案例不能当作真实收益样本。

### 经验层：有边界的纠错记忆

每条经验记录错误类型、当时证据、可复现的失败原因、改进假设、适用范围、验证样本与状态。复盘草稿先进入待验证池，未通过评估不得进入生产提示或自动改风控。

检索优先按 setup、结构阶段、位置和不确定因素匹配，补入相似反例；不能只按趋势标签取固定几条。严格排除当前样本及重叠窗口，开发、验证与测试的使用范围必须独立控制。

## 三、AI 如何做一次交易决策

已收盘行情 → 截止决策点的结构特征 → 相关规则与正反案例 → API 结构化判断 → 契约与证据校验 → 确定性风险裁决 → 自动执行 → 持仓与结果记录。

AI 输出主假设、备选假设、证据引用、setup 条件检查、候选计划或空仓原因。每个关键判断必须指向具体字段/根号/价位；事实不足时允许明确未定。不能以模型自报信心替代证据。

代码验证引用是否存在、来源是否在决策时刻可见、价格与订单方向是否合法，以及风险、费用、账户和交易所约束。AI 不直接跳过裁决调用下单权限。

每次决策存档输入数据边界、特征版本、知识与提示版本、模型标识、完整请求与响应、校验和裁决结果。历史摆动必须记录确认时刻，不能把之后才确认的极值提前画成当时已知结构。

初期用收盘事件驱动分析，避免每个价格跳动都调用模型。已挂订单或持仓的常规保护由代码持续运行，不等待模型回复。新决策与已有订单、仓位必须统一处理，防止重复入场。

## 四、复盘：先审决策质量，再看盈亏

### 第一步：冻结原决策

保留交易前证据、计划和规则版本，不能事后补理由。原判断不覆盖，修订意见另存。

### 第二步：隐藏结果进行重审

评审输入只包括当时可见的信息与当时规则；先独立重建判断，再与原决策比较。检查语境、位置、触发、目标、失效条件和不确定性，不以未来涨跌裁定对错。

同一个通用模型的自评可能重复原有偏见。确定性检查优先，关键争议进入人工裁定；可选另一模型交叉评审，但“多模型一致”仍不是事实证明。审计可用结构化理由和证据，不依赖获取模型内部思维过程。

### 第三步：核对执行事实

对比已批准计划与实际订单、成交、滑点、撤单、保护单和退出。区分模型提出违纪计划、代码错误放行、执行器偏离计划。计划在成交前被 gate 拒绝也需要复盘，不能只复盘已成交交易。

### 第四步：单独查看结果

| 决策与纪律 | 盈利 | 亏损 |
|---|---|---|
| 证据合理、纪律合规 | 保留为合规盈利样本 | 可能是预期内结果，不因单笔亏损改规则 |
| 判断失误或违纪 | 仍计为错误，不能奖励错误行为 | 按证据和执行链定位问题 |

遵守纪律是必要条件，不足以证明判断正确；判断合理也不保证现行策略具有优势。单笔无法判定“正常方差”或策略失效，累计分布偏离预期时另行检验。

### 第五步：归因与动作

- 感知错误：特征/时间边界/结构锚点错误 → 修代码并补针对性回归。
- 判断错误：当时已有反证被忽略、把第一腿当第二腿、目标序列错误 → 补有证据的反例或修改提示，评估后晋升。
- 纪律与裁决错误：计划违背规则、违规被放行 → 明确违规来源并修校验/风控。
- 执行错误：订单、保护、仓位或退出与批准计划不一致 → 修执行链与恢复机制。
- 暂未发现错误：保留结果并累计观察，不用“止损了”证明判断错，也不用“按计划退出”证明判断对。
- 证据不足/争议：暂不定论，不写入已确认的教学知识。

允许一笔交易有多个问题，避免只用一个类别掩盖因果链。当前 judge/reflect.py 的规则化初分不足：正常止损/止盈就归方差、到期就归执行偏差，必须改为上述基于证据的审计流程。

## 五、怎样证明系统进步

每轮只提出一个可检查的改进，例如“减少第一腿误判为第二腿”，而非笼统追求更高胜率。

流程：失败样本提出假设 → 开发集建立对照 → 冻结旧版和新版 → 验证集比较 → 达到预先约定条件才发布 → 独立留出集审计。测试集一旦反复用于选版本，就不再是独立留出，需要滚动增加新的未见时间段。

隔离同一行情的重叠决策窗口与未来结局窗口，时间边界须留出足够间隔；同一交易机会不能拆成几十个“独立”成功样本。检索库也遵守数据隔离。

评估分三层，不压成一个总分：

1. 知识与判断：关键事实错误率、证据可追溯率、setup 前置检查、失效条件完整性、相似反例辨别、重复判断稳定性。
2. 纪律与系统：违规提案率、违规放行率、重复订单、无保护仓位、状态恢复正确性。
3. 交易结果：净 R、回撤、成本、未成交、持仓时间及分 setup/周期表现，记录样本量和不确定性。市场效果必须用真实行情验证。

Gold 28/30 为空仓，永远空仓就有 93.33% 一致率。必须分别看候选召回、误报、理由质量；空仓样本也抽查是否错过合法机会，防止只审已交易样本。

模型或 API 版本变化应重新跑同一评估；记录服务端返回的模型标识和参数，不能假设不同时间的 API 输出完全可复现。

## 六、自动交易闭环

沿用 Python 核心，增加行情适配器、API 判断适配器、决策调度、订单执行、持仓状态机、持久化事件记录与复核评估任务。先采用单体服务，避免提前拆微服务。界面以监控、审计、暂停和查看证据为主。

订单必须有持久化业务标识和幂等键。下单超时先查询状态再决定重试；处理部分成交、撤单/成交竞态、精度与最小数量。重启时从交易所重建订单/仓位事实并与本地事件对账，未对齐时停止新开仓。

持仓管理实现固定止损/目标、结构化前提失效退出及到期退出。已成交仓位立即确认保护，保护失败时停止扩仓并按预定退出策略处理。暂停新开仓和紧急平仓是不同操作，既有保护不能随分析任务暂停而消失。

模型超时、格式错误、证据不足或行情陈旧：不产生新订单；已有仓位仍受确定性保护管理。配置账户总风险、单标的风险、并发仓位与亏损停机条件，明确这些约束与策略判断的分工。

交易所、现货/合约、标的、周期、资金上限和实盘启用条件尚未确定；后续执行设计须落实这些输入。此次文档与 Git 提交不代表授权真实账户交易。

## 七、落地顺序和验收

### M0：教学与规则可信

修正 gold 的确定事实错误，裁定 DOT/ds23 等争议，保留原件另立修订版本；修复自样本召回；统一两腿、CLV、净 RR 与失效条件。验收：每个候选可追溯前置条件与结构锚点，冻结集用于回归，另有隔离的评估数据。

### M1：可评估的 API 决策

接通结构化模型判断、输入快照和裁决，建立隐藏结果的评审及成对案例测试。验收：能完整处理合格、拒绝、空仓、无效响应与超时；可比较两个版本的具体错误，不能靠记住 gold 通过。

### M2：自动模拟交易与复盘

同一决策链驱动历史回放、实时影子运行与模拟执行；接通订单/仓位状态机、成本和失效退出；复盘先盲审后核对执行与结果。验收：不看未来、不重复订单、可恢复、违规盈利仍记错、合规亏损不自动改规。

### M3：受控发布与持续学习

达到预先约定的决策、风控、执行和统计门槛后，按用户明确的账户与风险范围启用有限实盘。改进提案先离线验证，再影子比较，最后发布并保留回滚版本。生产复盘不直接热改规则，不把单笔结果自动奖励给系统。

核心产物是一个“可审计、能验证改进、能执行交易”的系统。复盘笔记数量、模型措辞自信程度和漂亮的单次回测均不作为学会的证明。
