阅读全部 30 段标注，校验 SHA256、数据存在性、长度与元数据，使用前 180 根重新构建特征包，重点核对两张候选和文本中的可计算矛盾。未来 K 线只用于候选 outcome 对账。

本次是现有标注的证据审计，不是独立盲重标：已看过原始结论及两个候选的 outcome。未穷举每段所有潜在 setup，也未把未发现问题的标签宣布为正确。Python 环境缺 pytest，未执行 pytest 全套；校验与回放复算用现有无第三方依赖模块及标准库完成。

## 高优先级问题

### 1. 评估提示会召回当前样本自己的标签

位置：judge/prompt_builder.py 的 recall_examples/build_prompt；eval/gold_build.py。

召回没有接收当前 segment ID，也不按 split 过滤。30/30 gold 均在 knowledge/examples 中有同源样本。实测 APT、ARB、AVAX 三段会在自己的提示里看到同源草稿的 context 与 draft_verdict。

### 2. DOT 候选的结构口径没有闭合

文件：knowledge/gold/bn-DOTUSDT-4h-1767513600000.json。

标注说反弹两腿为 167H→169L→175H。原始 K 线中 169 后还有 171L=1.459、172L=1.452；不能把 169 当成完整回调终点而省略后续低点。当前 minor 摆动实际为 164L→166H→171L→175H，而当前 pack.pullback 返回 legs=1、two_legs=false、depth_ratio=0.6203，指向另一段已确认的主级别结构。

这不能简单判为“DOT 没有两腿”：原始行情可见局部两腿，主要问题是感知包选择的回调段与标注所审的当前段不一致。A2 卡明确要求腿数由特征包计，当前候选无法按该契约完整证实。

此外：(1.576−1.399)/(1.896−1.399)=35.61%，不是标注 38.7%；176 根 EMA≈1.579792，不能用决策根 EMA≈1.5694 解释当时触发。176 根大半在 EMA 下侧的条件仍可成立，数值错误本身不足以否决。

建议：列为“候选资格待重审”；先明确当前回调的起止锚点、确认时间与触发根，再更新特征和证据，不能仅因历史盈利或 gate pass 保留合格身份。

### 3. ds23 的失效条件与 B3 卡不一致

文件：knowledge/gold/ds23.json；knowledge/setups/B3-failed-breakout.md。

标注的失败突破位为 11.56，B3 卡要求价格重新收在突破方向位外即退出；标注却把平仓线写为突破极值 11.74，放宽了前提失效条件。首目标 10.43 和次目标 10.29 也需要分别说明为何属于“原结构对侧/更深 MM”，不能只以其为某个低点证明目标序列合法。

按两条候选失效线复核，首次未来收盘越线都在第 23 根（收 11.85），该根高点也已碰止损。因此本样本的标准回放结果没有因此改变，但规则语义仍应纠正。

标注称“上方无被套多头，所以下方空间干净”，推论不足；唯一敞开 short 缺口在下方也应审计支撑作用。此项为证据完整性问题，不能据此直接宣布候选无效。

### 4. XRP 空仓证据包含明确比较错误

文件：knowledge/gold/bn-XRPUSDT-15m-1723143600000.json。

标注同时写 179 收盘 0.5974，却称“未收回 0.6014 位内”；实际上 0.5974 < 0.6014。还把 178H=0.602 相对 167H=0.6014 写成“未创新高”。

空仓不一定错：178 收盘 0.6004 也低于 0.6014，未证实收盘突破；179 可能只是第一根回调，尚缺 B3 所需反向跟进。建议保留空仓为待证结论，重写突破成立条件、窗口计数和跟进证据，不能沿用原错误理由。

## 系统性证据问题

### CLV 的两种定义混用

perception/features.py 使用 (2C−H−L)/(H−L)，范围 [-1,1]。多份 gold 数值符合 (C−L)/(H−L)，范围 [0,1]。

例如 ds23 写 0.35，代码为 -0.30；DOT 写 0.59，代码为 0.1724；XRP 写 0.03，代码为 -0.9459。建议保留一种名称口径，另一种改名 close_location，并对全部案例重算，防止未来按正负判断方向时误判。

### 毛 RR 被写作净 RR

BTC-1693854000000：entry=25588、stop≈25673、target=25540，毛 RR≈0.565，按当前费用公式净 RR≈0.203，而标注称净 RR≈0.56。

FIL-1729667700000：entry=3.701、stop≈3.733、target=3.696，毛 RR=0.15625，净 RR≈0.03646，而标注称净 RR≈0.16。

两者仍应因 RR 不足空仓，但不能作为正确净 RR 的教材。

### 文本定性与枚举的语义不统一

AVAX 的 context 为上升，证据却称“实际是区间”；SUI 枚举为震荡，主假设称结构已转下。另有 WIF-15m、ds04、ds06、ds18 四段 gold 的 context 与当前确定性标签不同。后四段有人工覆盖标签的解释，不应机械视为错误。

建议区分“感知标签”和“判断语境”，明确哪个是评分目标；记录人工覆盖理由。ds04 的“LH+LL 方向互相矛盾”文字本身不成立，两者均指下行；区间判断需另给边界测试与重叠证据。

### 没有具体计划，不能从区间宽度推出 RR 必然不合格

AVAX 的“区间高度 1.8%，扣费后不可能满足 1.5 净 RR”缺少止损与目标；ds04 的“两侧各约 1.2% 都过不了 RR”也未定义计划。可以因位置/触发不合格空仓，但应删除这种无法验证的绝对推断。

### DOGE 突破状态前后矛盾

主假设写突破未确认，confidence_note 却写突破成立。179 收盘 0.17178 仍低于引用前高 0.17179。空仓可保留，突破状态和使用的沿口线需统一。

## 证据型 Gold 建设协议（新增设计）

目标是让 AI 学会“在正确语境和位置，经过可识别过程，出现充分触发后行动”，并主动检查反证。多因素不是多写理由；gold 必须能够检验每条证据及其组合是否真实成立。

### 1. 一个案例的最小审定内容

| 内容 | 必填信息 |
|---|---|
| 数据边界 | 标的、各周期、决策时刻、已收盘边界、原始数据哈希、结构确认时刻 |
| 规则身份 | core/setup/特征版本，现行规则或研究组合；不混合版本评分 |
| 结构地图 | 缺口账本、大小级别结构、预画支撑阻力、双方目标与 MM 锚点 |
| 证据矩阵 | 必需/增强/否决，各项满足/不满足/未定/不适用，根号价位及特征引用、同源依赖组 |
| 对立解释 | 最强反证、支持相反假设的事实、接管条件；区分已查无证据与数据缺失 |
| 动作 | 入场/等待/取消及原因；等待事实、候选有效期与重新审计条件 |
| 计划 | 当时可执行入场、结构外止损、前提失效、首目标、毛/净 RR、成本与下单类型 |
| 退出协议 | 止损、前提失效、固定目标、到期及优先级；主动止盈实验独立标版本 |
| 审定记录 | 各评审原始意见、分歧、证据修订、最终状态与理由 |
| 结果附件 | 成交/未成交、实际退出、净 R、执行偏差；不进入盲判输入 |

三推必须给出三段起止点和间隔回撤；二次测试必须指出同一测试对象、两次尝试及中间离开过程；MM 必须保存测量腿与投影基点的选用时间。不存在大级别原始行情时写“数据缺失”，不能用当前单周期片段虚构大级别阻力。

现有 JSON 尚无上述完整契约。建议新建独立版本的案例与校验结构，将证据、审定意见和结果分开存储；保留原 gold、MANIFEST 与原版本测试。schema/评分器同步升级后才能宣布修订版可用，不能仅给旧 JSON 添几个文字字段。

### 2. 深度案例试点

第一轮建议抽取 20 个独立事件，其中选择 10–15 个“三推到关键位置后测试”的事件做深度标注，其余加入其他结构或随机决策点作对照。数量用于打磨协议，不以此估计策略优势；不得为凑类别强行给标签。按事件时间选取决策点，不能只回头挑盈利的转折点。覆盖：

- 位置重合但只有第一推/第一测试，继续等待。
- 三推成立但动能仍推进，反转假设没有足够支持。
- 二次测试已发生但失败尚未确认，不能抢跑。
- 失败与触发齐全，但最近目标空间扣费后不足，取消入场。
- 完整证据支持入场且最终亏损；保留合规判断依据。
- 条件缺失却入场且最终盈利；保留违纪或判断错误标签。
- 突破获得接受的相似反例，取消反转方向。
- 出场前提失效、正常止损、目标、到期与限价未成交的不同路径。

同一机会可保存“观察—等待—触发”的多个决策快照，用于教学状态变化，但属于同一事件组，不能拆到不同数据集或计为多笔独立机会。先验选样池与结果展示池分别记来源，按结果挑选的教学案例不用于估计自然胜率。

### 3. 盲审与晋升流程

1. 先冻结可见数据和规则版本，删除原结论、未来 K 线和 outcome 后发给评审；知道历史答案的本轮审计不能充当新盲审。
2. 两份独立评审分别给证据矩阵、反证和动作，再比较。可使用不同 API 或独立上下文，但评审间不得先互看答案；同一模型的共同偏差仍需代码核验与人工审定。
3. 代码核对根号、确认时间、价格关系、结构计算和费用；人工处理语境与规则解释分歧。多数票不代替证据。
4. 分别标识“事实已核验”“决策已审定”“结果已复现”。三者互不替代；无法解决的候选留在争议集，标签不强行唯一化。
5. 先冻结决策评审，再揭示结果核对执行；不能因赚钱改判合格，也不能因亏损补写反证。
6. 审定案例晋升为修订版 gold，重建版本清单与评分基线；争议案例可作讨论材料，不当作检索中的确定答案。

新增组合未满足现行 C1/B3 要求的案例，只能按研究规则版本审定。不能为了“更多证据”给全部旧 setup 强加三推或二次测试，也不能因为额外条件多就免除原有门槛。

### 4. 质量门槛和分工

- 可计算事实必须可复现；错误引用、未来数据、毛净混淆未解决的案例不得标为证据已核验。
- 必需项未定、否决检查缺失或反证未裁定的案例，不作为确定的可入场答案。
- 以证据真实性、必需项覆盖、反证处理、动作时机与计划合法性评分；不按理由长度或条件数打分。
- 教学库服务检索，开发回归集服务调试，隔离验证/测试集服务版本比较；同事件、重叠窗口和结果标签不得跨边界泄漏。
- 以固定候选事件做条件消融，记录未成交/未触发、延迟和漏报；整个交易序列另验仓位冲突与净结果。新增条件是否有增量价值，要靠对照而非直觉。

先处理当前数据的 CLV、RR、XRP 比较错误、自样本召回等确定问题，再处理 DOT 两腿锚点与 ds23 失效/目标序列的争议，最后补充新结构族。详细决策与出场设计见同目录《应用建设方案-20261030.md》第三节。

### 5. 可执行的 Gold 生产流程

方法：代码准备事实 → 模型独立生成候选标注 → 确定性事实核验 → 人工裁定关键争议 → 冻结决策 → 揭示结果 → 发布版本。模型输出先进入待审池，不直接成为标准答案。此节定义流程与交付物，尚未实现生成工具或生产新 gold。

| 步骤 | 执行方式 | 交付物与检查 |
|---|---|---|
| 准备考题包 | 固定决策时刻，截取交易周期与大级别已收盘行情；附经过核验的结构特征和规则版本 | 数据边界、时间对齐、哈希与根号映射；不含原标签、未来行情或盈亏 |
| 抽取独立事件 | 从接近关键位、突破、回踩和再次测试等当时可观测事件抽样，并加入随机决策点 | 事件清单、抽样规则、随机种子、去重/重叠关系；选样不读取未来结果 |
| 独立标注 A/B | 两个独立上下文，优先不同模型；使用同一考题包，各自生成矩阵、反证与动作 | 两份原始响应与模型配置，提交前不互相展示；禁止检索同源答案 |
| 事实核验 | 代码检查引用、价格关系、确认时间、MM 与净 RR；尚无可靠检测器的三推/测试结构转人工核验 | 每项核验结果；区分通过、失败和无法核验，不能将未知视为通过 |
| 形成差异清单 | 对齐证据 ID，比较入场/等待、结构锚点、必要条件、失效线和目标 | 分歧定位到事实或规则，避免仅比较最终买卖标签 |
| 定向人工复核 | 优先审入场与等待分歧、结构解释分歧、无法定位的证据；随机抽审一部分一致答案 | 审定记录及理由；代码错误返回修复，未解决争议留池，不强行投票 |
| 冻结后揭示结果 | 先保存决策审定版本，再核对未来成交、退出与成本 | 决策质量与交易结果分别记录；结果不能改写原始判断依据 |
| 发布与隔离 | 审定案例生成版本清单，按事件与时间隔离用途 | 教学库、开发回归集、验证/测试集的准入清单及污染检查 |

代码负责可计算事实，模型负责提出结构解释，人工负责裁定无法机械决定的争议。代码本身也可能出错，因此复杂结构的事实核验需要对照原始 K 线；不能用同一个有缺陷的检测器同时生成并“证明”标签。

同意入场的两份答案也可能共享错误。例如双方都说“第二次测试失败”，却分别引用不同沿口，必须继续复核。一致答案的抽查范围和比例在批次开始前登记，不能只抽好看的例子；抽审发现系统性错误时扩大该类样本检查。

### 6. 用相邻决策快照教会等待

同一个事件按顺序构建快照：首次接近阻力 → 第一次测试后离开 → 再次测试 → 失败/突破接受 → 触发及空间检查。阶段是观察框架，真实行情可以跳过、延长或取消某阶段，不预设最后一定入场。

每个快照只使用该时刻的信息，分别生成并冻结标签。初次标注应在隔离上下文中进行，不能先展示事件最后一张图再回头标前面的“等待”。后续连贯性复核可以读取已冻结的前序快照，但不能用后序结果改写前序事实。

除完整矩阵外，记录：相对上一快照新增/失效的证据、当前动作、等待事实、取消条件、动作改变的直接依据。关键教学问题是“哪条新事实使等待变成可执行”，或“哪些反证使计划取消”。

同一事件的多个快照共享 event_id，整体分配数据集。快照数可以衡量标注工作量，独立事件数才用于报告机会数量；跨事件仍需检查行情与结果窗口重叠，不能仅凭不同 ID 宣称独立。

### 7. 每批验收与迭代

第一批 20 个事件先验证流程，记录：收到事件数、事实核验通过数、两评审动作/证据分歧数、人工抽审与争议裁定数、最终晋升数、留池原因，以及 API 用量和人工耗时。不规定必须晋升多少，不能为完成产量降低质量。

晋升前确认：必需证据可追溯、当时已可见、数值可复现；必要条件与反证已审定；计划和失效条件不矛盾；盲审输入无结果泄漏；教学与测试用途已隔离。等待/取消案例同样可以是高质量 gold，无须补出一笔交易计划。

对合理亏损与错误盈利，先按盲审质量标记，再用结果补充展示类别。若为了教学另行挑选特定盈亏案例，明确标为结果导向的补充样本，不混入自然抽样集估计策略效果。

合成单条件对照用于检查规则理解，真实行情案例用于判断可执行性与市场结果，两者分开统计。最终检查模型能否回答：“去掉哪条必要证据就不能入场，新增哪个已确认事实才允许行动？”这比复述案例结论更能检验是否理解规则边界。
