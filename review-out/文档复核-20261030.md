### P2 架构 §3"现有缺口"清单漏 3 条

1. **CLI gate 不传 `plan["context"]`**：`judge/pa_cli.py` 的 gate 分支只 update 了 side/setup，没写 context。即使补上台账，H6 仍会因 `context` 不在枚举而静默不查——文档只写了"未传台账"，会让人以为补台账即修好。
2. **费率双轨**：`net_rr` 读 config（限价入场 0.02%），`replay.simulate_trade` 硬编码 `FEE=0.0005`。限价单 H1 按 2.6257 承诺，回放却按市价费率结算。叠加第 1 条 naming 不一致（schema `order_type` vs gate `limit_in`），H1 实际上**永远**走市价费率。§6.1"费用口径按订单类型统一"目前无任何实现。
3. **召回退化比"不按 split 过滤"更严重**：`recall_examples` 每个 verdict 只取第一条，实测任何样本都只返回 2 条（`ex-APT` + `ex-ARB`）。只修 split 过滤，池子仍近似固定两条，与"按 setup/结构阶段/位置匹配、补相似反例"的要求差得远。

### P3 两处措辞会误导实现

- 阶段 A 把"CLV 问题"列进代码待修：代码只有一种定义，错在标注侧口径。应写成"重算标注 CLV 或把另一种改名为 close_location"，否则实现者会去改一个没错的函数。
- `knowledge/examples` 的 41 段（⊃ 30 段 gold）没有 split 字段，架构 §8.1 的表模型里也没有它的位置。迁移到 cases/annotations 时容易漏，建议明确"examples 池同样带 split 且按 split 召回"。

`eval/replay.py` 顶层 `import numpy`；本机两个 Python 均无 numpy、无 pytest，仓库也没有 requirements/pyproject。gold_run/gold_build 链路无法执行。gold 复核已注明"用标准库复算"，但"评估链路的依赖未声明"应进待办，否则阶段 A 的回归验收没有可执行入口。

## 四、gold 集合作为评估工具的效力

对"大部分是无效空仓"这一判断做数据核验（脚本复跑特征包，不引用标注原文）：

| 指标 | 实测 |
|---|---|
| 候选率 | 2/30 = 6.7% |
| 恒空仓基线 | 28/30 = 93.33% |
| 理由分布 | 位置不对 18 / 成色不合格 7 / 无命中 3 |
| 决策点落在要塞带内 | 22/28；其中"位置不对"组 14/18 |
| 决策点距最近摆动 ≤0.5% | 19/28；其中"位置不对"组 12/18 |

三层要分开说：

1. **结论层：空仓多数是对的。** 决策点不在荒野——22/28 价格就在要塞带内，19/28 距最近摆动不到 0.5%。价格到了位置、但没有触发就空仓，是 core 的纪律，不是判错。把这 28 条改标候选，等于教模型无触发入场，比空仓更糟。
2. **理由层：这才是负资产。** "位置不对"18 条里 14 条价格明明在带内，字面含义与事实相反——这个枚举实际在说"不是我想要的那类位置"，但没有任何可复核字段能支撑。另有约 1/4 的 no_trade 理由有明确事实错误（XRP 价格比较、AVAX 无计划 RR 推断、DOGE 自相矛盾、ds04 的 LH+LL、BTC/FIL 毛净混淆）。结论对、理由错，用来做教学会把错误因果固化。
3. **工具层：作为评估集基本无效。** 93.33% 的恒空仓基线、单一理由占 60%、B2/C1 零覆盖、无多单、限价/前提失效/到期退出零样本——无法区分"学会了"和"永远不做"。

根因不在标注员，在抽样协议：一段一决策、固定第 180 根，按钟表取点而不是按事件取点，候选率被结构性压到 6.7%。新文档的事件抽样方向是对的，但要加两条硬约束，否则会再产出一个 93% 空仓的集合：

- 每批预先登记**候选率区间**与各 setup 的最小覆盖数，不达标的批次不入库（不是事后解释空仓率）。
- 负样本的验收标准从"结论对"改成"**理由可机器复核**"：每条 no_trade 必须落到一条可计算事实（距要塞 X%、缺哪个必需项、命中哪条否决），落不到的留池，不进 gold。当前 18 条"位置不对"没有一条满足这条。

这 30 段的合理用途只剩两个：2 笔候选计划 + 硬数字作回归夹具；以及作为召回泄漏的检测样本。不应再作为一致率或泛化能力的证据。
