# 机会识别与决策机制修复纲领（2026-10-31，用户立项）

## 纪律（用户原话，最高优先）

**允许空仓，但每次空仓都要有依据；允许等待，但条件满足后不能不断
更换理由。** 目标不是多交易，是不该做时能拒绝、该做时有明确稳定的
行动依据。**本纲领不降低任何风控门槛**：gate H1–H8、位置执法、RR
地板全部不动；修的是识别与决策的问责机制。

与在跑工作的关系：分支预写三条款与 maps2 验证继续（预写端纪律，
是本纲领的同盟），但主线优先级让给本纲领四件。

## Build 1 · 拒绝理由可检查化（依据引用）

现状：pending 的 missing 是自由文本，「位置不对、成色不足」无法复核；
到达判读引用了哪些要求、无从分辨是规则还是临场加码。

- pending_conditions.missing[] 升级为结构化对象：
  {condition: 缺的必要条件, evidence: 第几根 K 线 / 哪个价位,
  basis: 出处}。basis 枚举：`branch:<point_id>`（冻结分支 trigger
  原文）/ `card:<setup>#<条目号>` / `skeleton:<条款>` /
  **`extra`（无规则出处、判读员额外加码）**。
- 到达提示纪律新增：引用冻结分支与卡片之外的要求，必须标 extra；
  extra 不许单独否决一个其余必要条件已满足的候选，只能作复核标记
  随判读落账。
- validate 硬校验：新判读 missing 缺 basis 即格式错；存量不回改。
- 度量：forward_anatomy 增「额外加码率」（extra 占全部缺项比例）
  为常驻指标，每批复跑。

## Build 2 · Setup 卡四分定版（充分条件）

现状：卡片条件是散文段落（如 B3「窗口内收盘收回位内 + 反向跟进」），
必要与加分不分，跟进这类要求归哪边没有定版——判读员只能全算必要。

- 每张卡重构四节：**必须有**（必要条件，逐条编号，供 Build 1 引用）
  / **加分项**（只影响评级，不影响合格）/ **否决项**（出现即不合格）
  / **封顶条款**（必须项齐 + 无否决 → 必须写候选；此后任何额外确认
  要求自动标 extra）。
- 推进方式：B3 先做样板——现卡触发里的「反向跟进」归必要还是加分，
  是第一个要定的点；样板经用户过目后推其余 6 张（A1/A2/B1/B2/C1/G1）。

## Build 3 · 等待对象化（等待 ≠ 取消）

现状：影子事件一次性判读，pending 随判读蒸发；下一次判读从零开始，
目标价天天可换——「昨天等回踩、今天等确认、明天嫌晚」的漂移在
机制上无人拦截。

- forward 新增 waits 注册表：判读产生 pending 且其 watch 可机械
  表述（价格进入某带 / 收盘越过某价 / 触及某点）时，登记为等待
  对象 {event, setup, point_id, recheck_condition, cancel_condition,
  frozen_branch}。
- 批量轮顺带扫 waits：命中 recheck → 以该根为新决策根重跑到达
  判读（地图与分支原文冻结不许改）；命中 cancel → 关闭记原因；
  都没中 → 继续等。
- 红线：recheck 判读只许核对冻结条件集；新增条件即 extra，计入
  Build 1 指标。

## Build 4 · 错误空仓考试

现状：考试只量过「与阿布对齐」，且总一致率会奖励永远空仓。

- 考卷三类：① **合法机会**（冻结规则满足、应出手）：Brooks 原册
  点名入场页、trainer 历史胜单决策根、影子已 tracked 单；
  ② **陷阱**（外观相似、缺一条真必要条件）：从 pending 里挑只差
  一条必要项的事件构造；③ **未完成片段**（应等待）：合法机会的
  决策根前移 N 根截断。
- 评分双轴：**漏检率**（① 被判 no_trade 的比例）与 **误放率**
  （②③ 被 qualified 的比例）分开记，总一致率不作 headline。
- 判卷纪律：只许用决策根及以前的信息；「后来涨了」不构成漏单
  证据——漏单只认「冻结条件在当时已满足而未行动」。

## 顺序

Build 2 样板（B3）与 Build 1 schema 同步出稿 → 用户过样板 →
批量推卡 + 提示/校验落地 → Build 3 注册表 → Build 4 考试验收。
