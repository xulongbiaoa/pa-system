# 价格行为学 AI 交易系统架构方案

Oct 30, 2026 · @xulongbiao

本方案把你的价格行为学资料拆成“代码能算的”和“必须由 AI 判断的”两部分，用统一的 JSON 契约和可回放的评估体系串起来，使任何 AI 工具都能接入，并且能量化证明它学会了没有。

## 现状诊断与设计原则

现有的 setup 谱（v3.1 整理稿）是一份研究笔记，不是执行指令：它把“识别、计数、测量、风控、复盘”全部压在同一份文本里，让 AI 一边读图一边背几十条补丁规则。

**文档本身暴露的问题**

- 补丁堆叠：几乎每个 v2.x 补丁都源自单局亏损（v2.9 来自四连亏），n=1 的结果触发了改规。
- 否决多于放行：四关只否决不放行，再加“弱过取消、不清楚不做”，第九局 20 个候选全灭、第十三局约 15 个全灭，附表 23 局里有 9 局是零交易。
- 感知不可靠：高低价靠目测、远边靠估读、画线工具连败三局、批量跳过 K 线漏看下破。这是读图错误，不是策略错误，但被记成了策略问题。
- 篇幅过长：一万多字的带版本号条文，AI 每根 K 线都要同时记住几十条条件，执行必然失真。
- 内部冲突：地图“冻结”与“活地图”并存，先验表里仍引用已取消的“弱过”。
- 先验未经本市场验证：Brooks 的 80%、40%、75% 等数字来自期货，直接套到加密货币日线上没有证据。

**六条设计原则**

1. **能算的交给代码**：摆动点、腿数、H/L 计数、EMA、重叠度、MM 目标、净 RR，全部由确定性代码产出，AI 不目测。
2. **只让 AI 做代码做不了的事**：语境判断、背景假设加权、setup 成色的定性判断、解释“为什么不做”。
3. **红线交给代码**：RR 门槛、止损位置、入场截止、禁止移损由裁决层强制，AI 的上下文里不再背禁令。
4. **知识按需加载**：常驻核心不超过 2000 字，每张 setup 卡片不超过 500 字，路由命中后只加载相关卡片。
5. **样本优先于条文**：用带标注的真实片段教会 AI，比再加一条 if 稳得多。
6. **规则只由证据修改**：单局盈亏不改规，改规必须有开发集证据并通过验证集确认。

## 知识库设计

知识库是纯 Markdown 加 JSON 的文件集合，与具体 AI 无关；它的核心目标是让每次调用只带必要的内容。

| 组成 | 大小上限 | 何时加载 | 内容 |
| --- | --- | --- | --- |
| 常驻核心 core.md | 2000 字 | 每次调用 | 交易者等式、五条红线、输出格式、空仓合法的声明 |
| 路由卡 router.md | 800 字 | 每次调用 | 趋势 / 区间 / 反转 / 空仓的判别条件，指向特征包的哪些字段 |
| setup 卡片 | 每张 500 字 | 路由命中后 | 见下方模板，约 12 到 16 张 |
| 先验表 priors.md | 每行一条 | 按语境检索 | 先验、出处、适用市场、验证状态 |
| 标注样本库 | 每段 JSON | 每次召回 3 到 5 段 | 真实片段 + 标注，正例反例各半 |
| 变更日志 changelog.md | 不限 | 从不进 AI 上下文 | 版本史、复盘故事、被取消的规则及原因 |

**setup 卡片模板（每张固定字段，便于代码检查完整性）**

1. 名称与编号（如 A1 M2B），出处（Brooks 原册 Video 号或手册章节）。
2. 适用语境：必须满足的特征包字段与阈值，例如“趋势状态 = 上升，回调腿数 = 2”。
3. 位置要求：允许的锚类型清单（要塞带、EMA、翻转区、区间边缘）。
4. 触发条件：信号 K 的定义，以及“合格 / 不合格”的判据，只有两档。
5. 止损规则：参照结构外加缓冲的计算口径。
6. 目标序列：最小目标、本腿 MM、下一要塞，各自的取法。
7. 失效与降级：什么情况下转分支 C 或作废。
8. 常见误判：不超过 3 条，各附一个反例样本编号。

**先验表字段**：先验陈述、数值、原册出处、原始适用市场与周期、本系统验证状态（未验证 / 开发集支持 / 验证集确认 / 被证伪）。验证状态为“未验证”的先验，AI 只能当作倾向，不能当作概率使用。

**标注样本库格式**：每段含 60 到 150 根 OHLC、特征包快照、标注（语境、主假设、命中的 setup、合格与否、入场止损目标、结果 R、标注者备注）。建议首批 40 段，其中至少三分之一是“应当空仓”的片段，避免 AI 学到“每段都有单”。

**从现有文档迁移**：把整理稿按上表拆开。底层判断辅助和缺口定义进感知层的代码口径；L1 语境路由进 router.md；分支 A 到 E 各拆成卡片；审计层四关里的硬数字进裁决层；附表里的实证对照改写成标注样本；所有“v2.x 补”和局号故事进 changelog.md。

## 感知层规格

感知层是一个纯函数：输入 OHLCV 数组和配置，输出特征包 JSON。同样的输入永远得到同样的输出，所以可以用单元测试验证。AI 只读特征包，不再自己数腿或估读价位。

**特征清单与口径（口径直接取自你文档里已定的规则）**

| 特征 | 口径 | 对应文档规则 |
| --- | --- | --- |
| 摆动点 | 收盘折线上的拐点，取拐点 K 的影线极值；回看窗口为配置项 | 缺口节“两种锚” |
| 腿 | 以反向摆动点为界；清一色同向 K 无反向摆动点，永远是一条腿 | 数腿 |
| H / L 计数 | 回调中越过前根高点的第一根为 H1；必须有新的回调极值才算 H2 | 数 H / L（v2.1） |
| 趋势状态 | HH+HL、LH+LL 的序列判定，输出连续分数而非单一标签 | 摆动结构 |
| 回调深度比 | 回调深度 ÷ 前进腿长度，并输出回调持续根数（20 根过期线） | 回调深度比、回调变质行 |
| EMA 读数 | EMA 值、斜率、K 线与 EMA 的位置、骑跨比例（实体在上方的占比） | EMA 读数、M2B 大半截 |
| 重叠度 | 信号 K 与前一根的重叠比例 | 重叠度 |
| 尝试计数 | 某价位带被到达次数与结局；收盘穿过才算穿越，盘中刺穿只记到达 | 尝试计数（v2.1 到 v2.4） |
| 要塞带 | 用协商段的收盘簇钉定上下边；钉不死就输出“远边未定”标记 | 要塞远边钉定 |
| 缺口账本 | 锚线、破于第几根、套深、套时、敞开或已解套、未遂次数 | 缺口节 v0.2 |
| 趋势年龄与高潮 | 根数、腿数、远离 EMA 的倍数（相对最近回调腿全长） | 趋势年龄、远离 EMA |
| MM 目标序列 | 最小目标、本腿 MM、下一要塞；异常根机械剔除后再测量 | 目标序列 ⑥⑦ |
| 费用与净 RR | 入场按挂单类型、出场一律市价，输出净风险与净回报 | RR 关净口径 |
| 数据质量 | 缺失根、异常根、成交量异常标记 | 测量卫生 |

**输出格式要点**

- 每个特征同时给“值”和“置信标记”（确定 / 边界 / 未定）。边界与未定的特征，AI 与裁决层都不得拿来作为放行依据。
- 每个价位都带“来源 K 线索引”，便于复盘时在图上定位。
- 配置集中在一个文件里：摆动回看窗口、缓冲倍数（ATR 的几分之几）、舍入格、手续费率。配置随版本号冻结。

**测试方法**

1. 手工构造 30 到 50 个小型数据集，答案已知（例如“恰好两腿的回调”“收盘穿越与盘中刺穿的区别”“实体骑跨 EMA”）。
2. 把你文档里已出现的歧义案例（第九至第十二局的各条歧义）各做成一个单元测试，口径以文档裁定为准。
3. 用一段真实数据人工标注后，对比代码输出，逐项统计一致率；一致率不足的特征不得进入判断层的放行依据。
4. 感知层单独版本化，改动口径必须同时更新测试与变更日志。

**已知难点**：摆动点的定义本身带主观成分（回看窗口大小会改变结果）。对策是同时输出两个尺度（大级别与小级别）的摆动点，并在特征包里明确标注级别，避免文档里反复出现的大小级别混淆。

## 判断层与 JSON 契约

判断层只回答三个代码答不了的问题：现在是什么语境（带权重的几个假设）、哪个 setup 的成色合格、不做的话原因是什么。统一输出结构化 JSON，既让任何 AI 都能接入，也让结果能被自动评分。

**一次调用的输入**

1. 常驻核心 + 路由卡（固定）。
2. 特征包（感知层输出）。
3. 最近 N 根 K 线（建议 60 到 120 根，OHLC 数值表，不用截图）。
4. 路由预选出的 setup 卡片（至多 3 张）。
5. 召回的标注样本（3 到 5 段，按特征相似度检索）。
6. 上一根的“假设账本”（见下）与当前持仓状态。

**输出 JSON 契约（字段含义，实际用 JSON Schema 校验）**

| 字段 | 内容 |
| --- | --- |
| hypotheses | 2 到 3 个背景假设，每个含：定性、权重（合计 1）、成立条件、作废条件、对应菜单 |
| weight\_moves | 相对上一根权重的搬动，每条写明触发事实（对应你的“证据只搬权重”规则） |
| primary | 主假设编号；权重过半易主时标记“菜单翻面” |
| candidates | 候选列表，每个含：setup 编号、方向、命中位置、合格 / 不合格、成色理由、需引用的特征字段 |
| plan | 通过候选的计划五格：入场、止损、目标序列、失效条件、仓位建议（比例，不含具体手数） |
| no\_trade\_reason | 无候选时必填，枚举：无命中 / 位置不对 / 成色不合格 / 背景不明 / 感知未定 |
| pending\_conditions | 候选挂起时，写明“重新合格的条件”（对应你的“形态不合格不是死刑”） |
| uncertainty | 本次判断依赖的哪些特征处于“边界 / 未定”状态 |

**提示词构造原则**

- 用 OHLC 数值表，不让 AI 看截图数腿；图只给人复盘用。
- 每条判断必须引用特征包字段名，不允许凭“感觉”下结论；没有引用的候选由校验器直接丢弃。
- 明确写出“空仓是合法输出”，并统计空仓率，避免 AI 为了显得有用而硬凑候选。
- 样本里同时展示“应当入场”和“应当空仓”，样本顺序随机，防止位置偏差。
- 温度调低并固定随机种子；同一输入跑 3 次取一致性，不一致的判断标记为低置信。

**假设账本**：每根 K 线结束时把 hypotheses 写入日志，下一根作为输入带回。这样背景是连续演化的，不会每根重新开始，也不会被第一印象冻死；每次权重搬动都有可追溯的触发事实。

## 裁决层

裁决层是几十行确定性代码：AI 提议，代码否决。它只能否决，不能替 AI 改计划，也不能放宽任何一条。凡是你文档里写成“红线”的内容，都放在这里，AI 的上下文里不再背这些禁令。

| 规则 | 校验方式 | 来源 |
| --- | --- | --- |
| 净 RR 门槛 | 按计划入场价、净费用重算，目标取序列中 AI 声明的那一级且须有 P 依据字段 | 审计第 4 关、目标序列 |
| 止损在结构外 | 止损与最近摆动极值、整数位的距离不小于缓冲 | 审计第 4 关 |
| 禁止缩止损、改近目标 | 持仓期间的修改请求一律拒绝 | 核心红线 |
| 单笔风险上限 | 风险金额不超过权益的 1% 到 1.5% | 执行节 |
| 入场截止 | 距窗口末尾不足 10 根不再开仓 | 入场截止 |
| 计划外成交 | 成交价偏离超过风险距离 25% 标注，超过 50% 平仓重审 | 成交偏差复核 |
| 引用完整性 | 候选必须引用特征包字段，且字段置信不是“未定” | 本方案新增 |
| 折扣兑现 | 若特征包标记抛物线高潮、踩踏继承、衰减边缘，则要求计划满足对应的收紧条件 | 折扣兑现总则 |
| 模式停牌 | 台账中样本不少于 3 且 0 胜的模式关闭 | 模式胜率台账 |

**输出**：每次裁决返回“通过 / 拒绝 + 命中的规则编号 + 数值明细”，写入日志。拒绝原因的统计就是后续改规的证据来源，例如“多少单死于净 RR 在 1.3 到 1.5 之间”。

**一条建议**：把“只否决”的规则分成硬规则（上表前六项，违反即拒绝）和软规则（折扣类，按成色降低仓位而非直接拒绝）。你文档里“否决过多导致零交易”的问题，多半出在软规则被当成了硬规则。

## 跨 AI 接入

三档接入共用同一套知识库、同一个特征包和同一个 JSON 契约，所以换模型只换最外层的适配器，资料不用改。

| 档位 | 做法 | 适用对象 | 局限 |
| --- | --- | --- | --- |
| A 粘贴式 | 脚本把“核心 + 路由卡 + 特征包 + 命中卡片 + 样本 + K 线表”拼成一个文本，粘贴给聊天窗口，AI 返回 JSON，再粘回脚本做裁决 | 任何聊天 AI，包括没有工具和 API 的 | 人工搬运，不适合批量 |
| B 工具式 | 感知层、裁决层、样本检索包成函数调用 / MCP / 命令行，AI 按需调用，例如“取特征包”“检索样本”“提交计划” | Claude、GPT、Gemini 等支持工具调用的 | 需要一次性写适配器 |
| C 自动式 | 一个循环程序逐根推进数据，调用 B 档的工具，写日志，并接入评估层批量回放 | 回放与实盘模拟 | 成本随根数线性增长，需设预算上限 |

**适配器要做的三件事**

1. 把统一提示模板转成各家的消息格式（系统提示、工具定义、结构化输出开关）。
2. 用 JSON Schema 校验输出，不合格就带着错误信息重试一次，仍失败记为“格式失败”并计入统计。
3. 记录模型名、版本、温度、种子、输入哈希，保证任何一次判断都可以复现。

**接新 AI 的验收流程**

- 第一步，跑感知一致性题集（30 道已知答案的读图题，答案由代码给出），低于 90% 的模型只允许看特征包，不许读原始 K 线。
- 第二步，在开发集上跑 100 段，检查格式失败率、空仓率、引用完整率。
- 第三步，与基线策略和其他模型比较期望 R，不达标的模型不接入实盘模拟。

**成本控制**：知识库分层加载本身就是省 token 的手段；回放时对“特征包显示无任何 setup 命中”的 K 线直接跳过判断，不调用 AI，通常能省掉大部分调用。

## 评估体系

评估层决定“学会了没有”。你现在的 23 局试验里，第六局一笔 +452.85 占了全部盈利的近一半，单局结果无法区分运气与优势，所以必须换成批量回放加固定数据切分。

**数据集切分**

| 集合 | 用途 | 规则 |
| --- | --- | --- |
| 开发集 | 调口径、调提示词、挑样本 | 可以反复看 |
| 验证集 | 检验改规是否真有效 | 每个改规提案只许用一次，用完换新的或标记已污染 |
| 最终测试集 | 定版后一次性报告 | 规则定版前不看，只开一次 |

切分按时间和品种双重隔离：同一品种同一时段不能同时出现在开发集与验证集，否则等于偷看答案。建议覆盖多个品种（至少趋势期、区间期、高潮反转各占一定比例），每段 150 根，与现有训练器一致，各集合至少 60 段。

**指标（以 R 为单位，不用金额）**

- 每笔 R 的均值与中位数、胜率、盈亏比、最大连续亏损、最大回撤（R）。
- 空仓率与“有候选但被裁决层拒绝”的占比，监控是否又滑向零交易。
- 各 setup × 语境的分项战绩，样本不足 30 笔的只展示不下结论。
- 感知一致率：AI 引用的特征与代码输出是否一致；格式失败率；同输入三次运行的一致率。
- 费用敏感性：把手续费加倍后期望 R 是否仍为正。

**必须同跑的对照**

1. 简单基线：例如“上升趋势里 EMA 回调后的第二信号入场、固定 1.5R 目标”，同样的裁决层与费用。
2. 随机入场基线：在同样的止损与目标下随机方向入场，用来确认费用与止损结构本身没有隐含优势或劣势。
3. 纯代码版本：把判断层替换成机械规则，用来量出 AI 判断层到底增加了多少价值。

复杂规则只有在期望 R 显著高于这三条基线时，才算有增量。

**统计底线**：笔数少于 100 时不报告胜率置信结论；报告期望 R 时给出自助法（bootstrap）置信区间；只要区间包含 0，就写“尚未证明优势”。

**感知与策略分开归因**：每笔亏损单标注原因类别，例如“感知错误”“背景误判”“成色误判”“先验不成立（20% 的尾巴）”“费用与滑点”，月度汇总。这是改规时区分“规则坏了”与“读图错了”的唯一办法。

## 学习闭环与治理

闭环的目的只有一个：让规则的每一次变化都有证据，并且不会重蹈“补丁堆叠”的覆辙。你 10 月 30 日拍板的“改规只由用户裁定、失败不自动加规”正好是这套流程的第一道闸门。

**改规流程**

1. 复盘产出“改规提案”，一个提案一个文件，必须写明：动的是交易者等式的哪一端（P、R 还是 P 的运行机制）、预期改变多少、证据局数与笔数、原册出处。
2. 入库门槛：同类样本不少于 3 个，或有原册定义出处；单局亏损只进台账，不触发提案；亏损先按“反思机制”一节的五类归因，只有 D、E 类才可能走到提案。
3. 在开发集上改并回放，对比改动前后的期望 R、空仓率、各分项战绩。
4. 在验证集上确认；开发集变好而验证集不变好，提案作废。
5. 由你裁定合入；合入时打版本号，一次只改一处，变更日志记录原因与回放结果。
6. 每合入 5 项改动，做一次“剪枝复审”：删掉近期没有被命中的分支或不再增加期望的规则（对应你的“剪枝优先于打补丁”）。

**版本管理**

- 知识库、感知层、裁决层、提示模板各自有版本号，评估报告记录四个版本的组合。
- 知识库放入 Git，每次提案一个分支，合入需要评估报告作为附件。
- 任何一次实盘模拟或回放结果都能回溯到当时的全部版本与随机种子。

**防过拟合的三个具体做法**

- 验证集“一次一用”：用过的验证段并入开发集，再补新的验证段。
- 参数不多于证据：每个新增阈值要说明它来自原册还是来自数据；来自数据的，要报告对阈值微调（上下 20%）的敏感度。
- 定期做前向测试：定版之后用新时间段的数据运行一个月，只记录不改规。

**与现有“用户裁定”机制的衔接**：AI 可以写提案、跑回放、给建议，但合入权在你。这条保持不变，只是让你裁定时有一份固定格式的证据，而不是凭一局印象。

## 反思机制：真提升还是补丁

核心原则：亏损本身不是改规的理由。反思的第一件事是判断“这笔亏损该不该引起任何改动”，大多数时候答案是不该。

**一、亏损先分类，每一类只允许对应的动作**

| 归因类别 | 判断依据 | 允许的动作 | 禁止的动作 |
| --- | --- | --- | --- |
| A 正常亏损（噪声） | 语境、setup、成色、RR、止损都合规，只是落在先验的那一端 | 记账；检查该 setup 的亏损占比是否仍在先验范围内 | 任何改规 |
| B 执行违规 | 违反了已有规则（移损、抢跑、计价错） | 强化裁决层的代码强制 | 改规则本身 |
| C 感知错误 | 数腿、估线、漏看 K 线 | 补感知层代码和单元测试 | 在知识库里加条文 |
| D 骨架内误判 | 规则对，但应用错了（如把中层线当要塞） | 往样本库补一个反例；必要时微调卡片“常见误判” | 新增分支或新 if |
| E 骨架外 | 规则确实没覆盖，且当时的信息足以做出更好的判断 | 进“骨架外池”，只登记不处理 | 立即改规 |

**归因配额监控**：你的体系自己写了 C2 约 80% 的突破会失败、MTR 成功率约 40%，长期来看总有相当比例的亏损应归入 A。如果反思把 90% 以上的亏损都归因到“可修的问题”，就是告警：它在给每笔亏损编故事，需要抽检。

**二、先盲重判，再揭盲对账**

事后看结果，AI 一定会“发现”当时的错误。所以反思分两步：

1. 盲重判：只给它到信号根为止的数据，重新做一遍判断，输出假设集与候选。
2. 揭盲对账：只比较三件事——原判断与盲重判是否一致；用到的信息是否全部在当时可得；亏损属于哪一类。

“事后最优但当时不合法”的情形一律归入 A，不许追认，这条做成流程里的硬步骤。

**三、补丁检查清单（提案必须全部通过）**

- 去个案化：把规则改写成一句话，不含这一局的价位、品种、局号；改写不出来的就是补丁。
- 找同类：在开发集里找到至少 3 个其他命中该条件的片段，并统计加了这条之后期望 R 变好、持平还是变差。
- 验证集确认：在没参与过提案的数据上指标要改善，不是只在出事的那一局变好。
- 说清等式的哪一端：动的是 P、R 还是 P 的运行机制，说不清不入库。
- 有出处或有统计：来自原册定义或本系统数据统计，不来自“这次亏了”。
- 复杂度预算：核心与卡片的总字数设上限，新增一条必须删除一条，这是最有效的反补丁机制，相当于机器学习里的正则化。

**四、能力真的提升，看这些指标（都在没见过的数据上测）**

- 感知一致率：AI 引用的特征与代码输出是否一致。
- 分类准确率：在保留的标注样本上，语境与 setup 的判断准确率。
- 校准度：它说“偏多 70%”的那些情形，实际命中率是否接近 70%。判断好不好，只能靠大量样本上概率是否准来衡量，不能靠单次结果。
- 稳定性：同输入多次运行的一致率，以及换模型后的一致率。
- 副作用：验证集的期望 R 与空仓率没有因为加规则而滑向零交易。

**五、反思流程的机制设计**

- 批量更新，不逐笔更新：每笔只产出归因标签；每 30 到 50 笔汇总一次，看归因分布是否偏移，偏移才是信号。逐笔反思等于对单个样本做梯度更新，必然过拟合。
- 反思者与评审者分离：反思者只能输出归因、证据和候选反例，禁止输出“新增规则”；提案走独立流程，由评审者专门找反例，问“这条在哪些已有样本上会出错”。
- 骨架外池：E 类只登记，同类累计到 3 个以上并通过上面的清单，才进入改规流程；长期积累不起来的就是噪声，不是规则缺口。
- 允许结论是“无可改进，属于概率内的亏损”，模板里明确保留这个选项，并在 A 类成立时鼓励选它。

**六、反思输出模板（new\_rule\_proposed 固定为 false，改规走独立提案流程）**

```json
{
  "blind_rejudge": "盲重判结论（仅用信号根之前的数据）",
  "matches_original": true,
  "info_available_at_time": true,
  "category": "A | B | C | D | E",
  "evidence": ["引用的特征字段或违反的规则编号"],
  "in_prior_range": "该 setup 的亏损占比是否仍在先验内",
  "allowed_action": "记账 | 强化裁决 | 补感知测试 | 补反例样本 | 入骨架外池",
  "new_rule_proposed": false
}
```

**七、两个角色的提示词要点**

| 角色 | 输入 | 必须做 | 明令禁止 |
| --- | --- | --- | --- |
| 反思者 | 交易记录、盲重判结果、特征包、裁决层日志 | 先盲重判再对账；给出类别与证据；A 类要写明“为什么这是概率内的亏损” | 输出新规则；使用信号根之后的信息去解释当时的判断；写“应当早就看出” |
| 评审者 | 一份改规提案、开发集、样本库 | 找出该规则会判错的 3 个已有样本；检查清单逐项打勾；判断是否能被已有规则的参数化解释 | 因为“听起来合理”而通过；评审时参考提案者的结论而不是数据 |

## 进一步增强效果的做法

下面几项按“投入小、收益确定”的顺序排列，建议在路线图第 5 阶段之后逐项加入，每项加入前后都用评估层对比。

| 做法 | 做什么 | 为什么有效 |
| --- | --- | --- |
| 金标准回归集 | 挑 30 段人工反复确认过的样本，作为只读集合；任何知识库或提示改动后必须全部重跑，通过率不得下降 | 防止改一处坏一处，这是反补丁的最后一道自动防线 |
| 反例挖掘 | 用代码在数据里自动找“特征包相似、但结果相反”的片段对，交给你标注 | 标注预算有限时，边界样本的信息量远高于典型样本 |
| 多模型交叉判断 | 同一输入让 2 到 3 个模型各出 JSON，分歧大的判断降为低置信，只允许软仓位 | 分歧本身就是不确定性的度量，不需要靠 AI 自称“有把握” |
| 置信度校准表 | 每月统计各置信档的实际命中率，画成校准表；偏离大的档位自动降权 | 把“AI 说有把握”变成可核对的数字 |
| 分语境分层评估 | 所有指标按趋势 / 区间 / 高潮后 / 宽通道分层统计 | 你的台账早已发现分界线是语境；分层才能看出真问题在哪一层 |
| 漂移监控 | 滚动窗口比较近期与开发集的特征分布、空仓率、归因分布 | 市场状态变了、而不是规则坏了，两者的处理完全不同 |
| 影子模式 | 定版后让系统每天对新数据出计划但不下单，与实际走势对账一个月 | 在零成本下取得真正的样本外证据 |
| 提示与样本的 A/B | 换样本、换顺序、换措辞，用评估集比较，不凭感觉选 | 提示词的效果同样需要实验，而不是文字游戏 |
| 失败样本库 | 把 A 类亏损与 D 类误判都做成带标注的样本，加入召回池 | 让 AI 学到“合规也会亏”，把纪律与结果分开 |
| 人工抽检 | 每周随机抽 5 笔判断，由你亲自对照图盲评，与 AI 的结论比对 | 你是体系的原作者，是最可靠的质量信号，也能发现自动指标看不到的偏差 |

**两个容易被忽略的点**

- 评价单位用“过程分”而不是“结果分”：每笔单按“语境判断、位置、成色、RR、执行、纪律”六项各打分，亏损但过程满分的单，在报告里应当是好单。长期看，过程分与期望 R 的相关性，才能验证“纪律没问题”是否真的对应正期望。
- 给体系设“退出条件”：事先写好，例如“前向 100 笔期望 R 的置信区间上限仍低于 0，则整套停用并回到原册重审”。没有退出条件的系统，只会不断加补丁。

| 环节 | 建议选择 | 理由 |
| --- | --- | --- |
| 语言 | Python 3.11 以上 | 数据处理库齐全，你的现有工具也可对接 |
| 数值与数据 | pandas、numpy | K 线与特征计算 |
| 校验 | jsonschema 或 pydantic | 契约校验、格式失败重试 |
| 测试 | pytest | 感知层口径回归 |

| 工具接入 | MCP 服务器或各家函数调用，二选一起步 | 先接你最常用的一个 AI，再扩展 |
| 版本 | Git | 知识库与代码同仓，评估报告随提交保存 |

数据来源建议先固定为一个交易所的历史数据并本地缓存，保证回放可复现；复权、缺失根和时区在数据加载层一次处理，不让后面各层各自处理。

## 分阶段路线图

十二周、每阶段都有可检查的交付物和验收标准，前一阶段验收通过才进入下一阶段。

| 阶段 | 周 | 交付物 | 验收标准 |
| --- | --- | --- | --- |
| 0 冻结与拆分 | 第 1 周 | 现有整理稿冻结为附册；拆出 core.md、router.md、10 到 16 张 setup 卡片；changelog 收纳所有补丁史；写好复杂度预算（核心与卡片总字数上限）和体系退出条件 | core.md 不超过 2000 字，每张卡片通过字段完整性检查；退出条件写成可判定的一句话 |
| 1 数据与样本 | 第 1 到 2 周 | 固定数据源、本地缓存；按品种与时间切出开发集、验证集、测试集；标注首批 40 段样本，其中 30 段定为金标准回归集（只读） | 三个集合无时间品种重叠；样本中应空仓的不少于三分之一；金标准集经你亲自复核 |
| 2 感知层 | 第 2 到 3 周 | features.py 与全部单元测试；歧义案例转成测试 | 单元测试全过；与人工标注的一致率每项特征不低于 90%，未达标的特征标记“未定” |
| 3 契约与粘贴式 | 第 3 到 4 周 | 两份 JSON Schema（判断输出、反思输出）、prompt\_builder、A 档粘贴脚本 | 3 个不同 AI 对同一 20 段片段都能产出合格 JSON，格式失败率低于 5%；反思模板中 new\_rule\_proposed 被校验器强制为 false |
| 4 裁决层与回放 | 第 4 到 5 周 | risk\_rules.py、replay.py、两条基线；日志加入过程分六项（语境、位置、成色、RR、执行、纪律） | 回放可复现（同输入同输出）；基线结果出炉并存档；每笔单都有过程分 |
| 5 首轮开发集评估 | 第 5 到 6 周 | 第一份评估报告：期望 R、空仓率、按五类归因的亏损分布、归因配额基线、置信度校准表初版、分语境分层指标 | 报告含对照基线与置信区间；A 类占比与先验推算范围对照完毕，作为后续改动的起点 |
| 6 工具式与反思闭环 | 第 6 到 8 周 | B 档工具接入；反思者与评审者提示词上线；每 30 到 50 笔批量反思；提案不超过 3 个并全部通过补丁检查清单 | 每个提案都有开发集与验证集对比；金标准回归集通过率不下降；空仓率没有滑向零交易 |
| 7 前向与影子试跑 | 第 9 到 10 周 | 定版后新数据一个月影子模式（出计划不下单），只记录不改规；每周人工抽检 5 笔 | 前向期望 R 与开发集的差距在可解释范围内；校准表无明显偏离；未触发退出条件，才考虑小仓位实盘 |
| 8 增强项 | 第 11 到 12 周 | 按收益顺序逐项加入：多模型交叉判断、反例挖掘、漂移监控、提示与样本的 A/B | 每项加入前后各跑一次评估，期望 R 与分层指标不退化才保留，否则回退 |

**每周固定动作**：周一定本周目标，周五出一页回顾（做了什么、指标变化、下周计划），回顾中不允许出现“再加一条规则”之类没有证据的结论。

**可以砍掉的部分**：如果时间紧，先做阶段 0 到 3 并只用粘贴式，已经能得到“特征包加合格 JSON 加人工裁决”的半自动工作流，效果通常已明显好于直接把整理稿喂给 AI。

## 风险与失败模式

| 风险 | 表现 | 对策 |
| --- | --- | --- |
| 体系本身没有优势 | 评估层结果期望 R 的置信区间包含 0 | 这是评估层存在的意义：在投入真钱前发现；不通过就回到原册找能区分赢家的条件，而不是加规则 |
| 感知口径有争议 | 摆动点回看窗口不同，结果不同 | 输出两个尺度并标注级别；口径写入配置并冻结，争议案例做成单元测试 |
| AI 判断不稳定 | 同输入三次结果不一致 | 低温度加固定种子；不一致的判断标记低置信，裁决层按软规则降仓位 |
| 空仓率过高 | 又回到“十个候选全灭” | 监控空仓率与被拒绝占比；软规则降仓位而非拒绝；定期复审哪条规则杀掉最多本应盈利的单 |
| 样本过少 | 150 根一段、笔数有限，结论不稳 | 增加段数与品种；笔数不足 100 时不下胜率结论；只报告期望 R 的区间 |
| 数据窥探 | 反复在同一批数据上调规则 | 验证集一次一用；最终测试集只开一次；改动一次一处 |
| 先验不适用 | Brooks 数字来自期货，加密货币日线不同 | 先验表保留“验证状态”字段；未验证的只当倾向，用开发集统计本市场的实际比例 |
| 费用与滑点吞噬优势 | 小止损下毛利被手续费吃掉两成以上 | 评估里做费用加倍敏感性；裁决层按净口径算 RR；小级别、小止损的 setup 优先降权 |
| 样本标注偏差 | 标注者事后诸葛，标成“当时合法” | 标注时只给到该根 K 线为止的数据，揭盲后另行标注结果；复盘区分“树内合法”与“事后最优” |
| 工具与接口变化 | 某个 AI 的 API 更新 | 适配器隔离在 adapters 目录；核心逻辑不依赖任何一家的特性 |
| 实盘心理与执行 | 回放有效，实盘不照做 | 先小仓位前向试跑；所有计划由裁决层输出，执行时不临场改动 |

**一条总体提醒**：这套架构能让 AI 稳定、可复现地执行你的体系，并能用数据判断体系有没有优势；它不能保证体系盈利。在评估层给出正向且稳健的结果之前，不建议投入需要承担亏损的资金。本方案不构成投资建议。
